# ANALYSIS.md — Фаза 1: проучване преди програмиране

Дата на анализа: 26.09.2026

Документът описва какво **реално** е налично за мобилното приложение на
НЧ „Васил Левски – 1922“, с. Яворец, и какво **липсва**. Приложението е
построено върху тези изводи. Нито един API адрес, формат или функция не е
измислен. Където нещо липсва, това е казано изрично, а в кода има интерфейс,
временна реализация и описание на нужния API.

## 1. chyavorec.org

### 1.1 Платформа

Сайтът работи на **uCoz** (облачна CMS). Съдържанието се поддържа от:

- **Template Builder** — главният „skeleton“ (навигация, начална страница `#hp`,
  основна колона `#mc`);
- **Page Editor** — отделни страници с адреси `/index/<име>/0-<N>`;
- **модули**: „Новини на сайта“ (`/news/`), „Фотоалбуми“ (`/photo/`),
  „Каталог на файлове“ (`/load/`), форми за контакт (`[EMAILFORM]`).

Няма WordPress и няма WordPress REST API. uCoz има **uAPI**, но той изисква
OAuth ключове на собственика на сайта и не е публичен — не се използва.

### 1.2 Откъде идват данните — избран метод по приоритет

| Данни | Източник | Метод | Приоритет по заданието |
|---|---|---|---|
| Новини | модул „Новини на сайта“ | **RSS 2.0** `https://chyavorec.org/news/rss/` (генерира се автоматично от uCoz) | 2. RSS |
| Пълна статия | страницата на новината | контролирано извличане на `.eMessage` / `.eText` (стандартни uCoz класове) и персонализираните `ec-*` шаблони | 4. парсер (само за тялото) |
| Галерия | модул „Фотоалбуми“ | **RSS** `https://chyavorec.org/photo/rss/`; албумите = категориите в RSS | 2. RSS |
| Страници (история, библиотека, фолклорна група, клубове, проекти, дигитален клуб, дарения…) | Page Editor | откриване от менюто на началната страница + извличане на блокове от `#mc` | 3./4. |
| Събития | няма отделен модул; има страница „Събития“ и новини в категория | новини с категория „Събития“ + блокове със заглавие и дата от страницата „Събития“ | 2. + 4. |
| Контакти | страница „Контакти“ | `tel:` / `mailto:` връзки, адрес и работно време от текста | 4. |
| Политика за поверителност | ако има страница в менюто | откриване от менюто (заглавие съдържа „поверителност“/„лични данни“) | 3. |

Известните адреси на страниците (от менюто на сайта към момента на анализа) —
използват се само като резервен вариант, ако менюто не се зареди:

| Раздел | Адрес |
|---|---|
| Събития | `/index/events/0-58` |
| Библиотека | `/index/library/0-59` |
| Фолклорна група | `/index/folklorna_grupa/0-60` |
| Народни танци | `/index/tancov_klub/0-61` |
| Клубове и кръжоци | `/index/klubove_i_krzhoci/0-62` |
| Проекти | `/index/proekti/0-63` |
| История | `/index/history/0-64` |
| Контакти | `/index/kontakti/0-65` |
| Електронен каталог | `/index/elektronen_katalog/0-70` |

Реализация: `shared/src/main/kotlin/org/chyavorec/data/site/` —
`UcozRssParser`, `HtmlContentExtractor`, `SiteLinkClassifier`,
`EventExtractor`, `ContactsExtractor`, `ChyavorecSiteService`.

### 1.3 Защо не „fragile scraping“

- Новините и снимките идват от **структурирани RSS емисии**, не от HTML.
- Страниците се превръщат в **семантични блокове** (заглавие, параграф, списък,
  снимка, цитат, файл), а не се копират като HTML — промяна в CSS на сайта не
  чупи приложението.
- Навигацията се **открива** от менюто → нова страница в сайта (напр.
  „Дигитален клуб“) се появява в приложението без нова версия.
- Всичко се **кешира** и при грешка се показват последните данни с дата.
- Няма WebView за съдържание (само Custom Tab за външни връзки).

## 2. invlib.com / InvLib („Инвентар“)

### 2.1 Какво е InvLib

InvLib е **безплатна програма с отворен код (GPL-3.0)** за управление на
малки български библиотеки по Наредба № 3 от 18.11.2014 г. Уебсайтът
invlib.com е сайтът на самата програма. Изходният код и изданията са в
GitHub: `plam4o4o-source/yavorec-katalog`.

Технически:

- **Офлайн настолно приложение за Windows** (Electron + SQLite, `better-sqlite3`);
- базата е **локален файл** на компютъра на библиотеката (или споделена папка
  в локалната мрежа);
- комуникацията е вътрешна (Electron IPC: `readers:get`, `loans:*`,
  `holds:*`…) — **няма HTTP сървър, няма REST API, няма OAuth, няма онлайн
  вход за читатели**;
- програмата публикува **публичен онлайн каталог**: файл `katalog.json`,
  който записва в git хранилище и качва в GitHub при всяка промяна (на всеки
  5 минути, ако има промени). Сайтът го чете на живо.

**Извод:** на invlib.com и в InvLib няма публичен API за читатели. Наличието
на читателски карти, заемания и срокове в програмата **не означава** онлайн
достъп до тях.

### 2.2 Публичен каталог — реален формат (използван от приложението)

Адреси (същите като на страницата „Електронен каталог“):

- основен: `https://raw.githubusercontent.com/plam4o4o-source/yavorec-katalog/main/katalog.json`
- резервен: `https://cdn.jsdelivr.net/gh/plam4o4o-source/yavorec-katalog@main/katalog.json`

Структура (от `buildCatalogPayload()` / `publicBookFields()` в `electron-app/main.js`):

```json
{
  "library": "Библиотека при НЧ …",
  "place": "с. Яворец, …",
  "generated": "2026-09-19",
  "items": [
    {"inv":399666,"a":"Джиан, Филип","t":"\"Ох...\"","s":"","c":"","p":"","y":"2016",
     "v":"книга","l":"български","u":"8","g":"ЦБ/840/Д 51","o":"за възрастни",
     "k":"","n":"","cv":"","av":1,"d":"2023-07-13"}
  ],
  "shelves": [ {"name":"най търсени","items":[156,187,111]} ]
}
```

| Ключ | Значение | Колона в InvLib |
|---|---|---|
| `inv` | инвентарен номер | `books.inv_number` |
| `a` | автор | `books.author` |
| `t` / `s` | заглавие / подзаглавие | `title` / `subtitle` |
| `c` / `p` / `y` | град / издател / година | `city` / `publisher` / `year` |
| `v` | вид документ (книга, видеодокумент…) | `categories.name` |
| `l` | език (публичен надпис) | `language` |
| `u` | УДК индекс | `udk` |
| `g` | сигнатура | `call_number` |
| `o` | отдел (за възрастни, за деца…) | `department` |
| `k` / `n` | ключови думи / анотация | `keywords` / `annotation` |
| `cv` | адрес на корица | `cover_url` |
| `av` | 1 = налична (статус „наличен“ **и** свободни бройки) | изчислено |
| `d` | дата на постъпване | `register_date` |
| `shelves` | витрини („най-търсени“ и др.) | `catalog_shelves` |

Какво **НЕ** се публикува (нарочно, заради ОРЗД): читатели, заемания,
отчислени и служебни документи. **ISBN не се публикува** (`books.isbn`
съществува в базата, но не е в `publicBookFields`).

### 2.3 Функции по заданието срещу реалната наличност

| Функция | Налично ли е публично? | Какво прави приложението |
|---|---|---|
| Каталог: търсене по заглавие, автор, ключова дума, инв. номер | ✅ katalog.json | реално, офлайн-способно търсене |
| Търсене по ISBN | ⚠️ няма ISBN в JSON | полето се поддържа (ключ `i`), работи щом InvLib го добави |
| Филтри: вид, отдел, език, раздел по УДК (жанр), година; сортиране | ✅ | реално |
| Наличност на книга | ⚠️ само „налична / не е на рафта“ (`av`) | показва се с дата на данните; „заета“ vs „недостъпна“ изисква API |
| Витрини / нови постъпления | ✅ `shelves`, `d` | на началния екран |
| Вход на читател | ❌ | интерфейс + клиент по предложения договор; в production — честно съобщение |
| Читателски профил | ❌ | същото |
| Читателска карта | ❌ онлайн; ✅ формат: InvLib печата картите в **Code 39** | читателят може сам да въведе номера от картата си → баркод Code 39 (шифрован, отбелязан като непроверен) |
| Заети книги, срокове | ❌ | интерфейс + индикатор на сроковете от реалните дати, щом има API |
| Членство, валидност | ❌ | същото |
| „Заяви книгата“ | ❌ (в InvLib има таблица `holds`, но не и онлайн достъп) | бутонът се показва **само** ако сървърът обяви `holds: true` |
| Забравена парола | ❌ | бутонът се показва **само** ако сървърът обяви `passwordReset: true` |
| Push известия за срокове | ❌ | локални известия (WorkManager), щом има API за заемания |

### 2.4 Какво трябва да предостави разработчикът на InvLib

Пълният договор е в [`docs/API.md`](docs/API.md). Накратко: малък HTTPS
сървър (или мост към базата на InvLib), който реализира:

1. `GET /v1/capabilities`
2. `POST /v1/auth/login`, `POST /v1/auth/refresh`, `POST /v1/auth/logout`
   (+ по избор `POST /v1/auth/password-reset`)
3. `GET /v1/me` — профил
4. `GET /v1/me/loans` — заемания със срокове
5. `GET /v1/me/membership` — регистрация/членство и валидност
6. по избор: `POST /v1/me/holds`, `POST /v1/me/loans/{id}/renew`,
   `GET /v1/books/{inv}/availability`, `DELETE /v1/me`
7. в `katalog.json`: ключ `i` (ISBN)

Тъй като InvLib е офлайн програма на Windows, най-реалистичният вариант е
отделна услуга („мост“), която чете копие на SQLite базата (само нужните
колони) и работи на сървър/хостинг — виж раздел „Архитектура на моста“ в API.md.

## 3. Технологичен избор

| Решение | Причина |
|---|---|
| Kotlin + Jetpack Compose + Material 3 | съвременен native UI, достъпност, анимации |
| Два модула: `shared` (чист Kotlin/JVM) + `app` (Android) | домейнът, парсерите и услугите се тестват без Android; ясна граница |
| OkHttp + kotlinx.serialization + Jsoup | стабилни библиотеки; Jsoup за RSS/HTML |
| Файлов кеш за съдържание, Room за любими/напомняния, DataStore за настройки | katalog.json е над 2 MB (над лимита на SQLite CursorWindow) |
| Android Keystore (AES-256-GCM) | сесия, ръчно въведена карта и читателски кеш — шифровани |
| WorkManager | фонова синхронизация и локални известия без сървър |
| ZXing (само кодиране) | Code 39 баркод и QR за картата |
| minSdk 26 (Android 8.0) | adaptive икони, java.time, Keystore AES-GCM; >97% от устройствата |
| targetSdk / compileSdk 36 | изискване на Google Play към 2026 г. |
| Без Firebase | няма backend за push; без проследяване и без google-services.json |

## 4. Проверка след първото пускане (срещу живия сайт)

Понеже средата за разработка нямаше достъп до chyavorec.org, при първото
пускане трябва да се провери (5 минути):

1. **Новини** — зареждат ли се (RSS `/news/rss/` трябва да е включен в
   настройките на модула „Новини“ в uCoz — по подразбиране е включен).
2. **Галерия** — RSS `/photo/rss/` (включен в модула „Фотоалбуми“).
3. **Дейности** — появяват ли се страниците от менюто; ако някоя липсва,
   провери дали е в менюто на началната страница.
4. **Контакти** — извлечени ли са телефон, имейл, адрес, работно време.
5. **Събития** — за най-добър резултат новините за събития да са в категория
   „Събития“ и в текста да има дата („12 октомври 2026 г., 18:00 ч.“),
   „Място: …“ и „Организатор: …“.
